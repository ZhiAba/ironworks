## 关键技术结论（已验证，别再试错）
1. 内容名自动加前缀 `ironworks-`；贴图文件名**不加**前缀
2. 本地化键必须带前缀：`item./block./status./recipe.ironworks-xxx`
3. Android 走 `classes.dex`，桌面走 `.class`，同一个 jar 里两者都要有
4. `ConsumeLiquidsDynamic` 的 amount 是**每 tick**；Recipe 按每 craft 写，库内按 craftTime 折算
5. 炮塔弹药必须走 `build.handleItem()`，直接 `items.add` 不进弹药槽
6. 测 DPS 必须用**静态靶**（敌方 thorium-wall）；单位靶会自己走
7. 多格方块 `setBlock` **以点击格为中心**（offset=-(size-1)/2），3x3 会覆盖周围一圈
8. `StatusEffect` 没有「受到伤害 +X%」钩子
9. **护甲可以用 `unit.statusArmor(x)`**（内部是动态状态的 armorOverride，覆盖语义）
10. `Damage.damage` 打建筑是射线法 → 实际建筑伤害 ≈ 标称 3~4 倍
11. 自定义 Block 的 Building 要 import `mindustry.gen.Building`；`tilesize` 在 `Vars`
12. 状态时长以 **tick** 计；`apply(status, 1)` 只有一帧（测试踩过）
13. 转炉不耗电：铁水自带显热，早期不该用电炉炼钢
14. `ConsumePowerDynamic` 在配方 power=0 时效率恒为 0（没接电网）→ MultiCrafter 已覆写
15. 液体不能做科技树节点（原版同样）
16. 科技树：两条线直接挂 `Blocks.coreShard`；**物品节点不给成本**（获得即解锁，靠 Produce 目标），
    建筑节点才付研究成本（0.27.0 修正）
17. 材料分级是两轴：字母档(D/C/B/A)=获取难度+强度，数字=加工层数；同档不同层不代表谁更高级
18. 钢铁链锚在钛(C档)而不是巨浪合金(B档)：原料是 D 档、产品是 C 档
19. **塞普罗没有氮气**：原版氮气只由埃里克尔空分机产出；模组已补空气分离机（0.22.0）
20. 外挂装甲/多单位已搁置，等用户提供其他模组实现
21. **数据库可见性**：内容必须有 `shownPlanets`，否则物品/液体/状态在数据库行星页签下整类隐藏（0.25.0）
22. 液体容量是**按每种液体**算的；跨方块输送靠 `dumpLiquid`
25. 多液体产出必须按产出下标分方向（`liquidOutputDirections[i]`），否则会混料（0.29.0）；
    单液体产出才可以四面输出
23. 所有带液体的方块必须是 MultiCrafter（白名单），GenericCrafter 会收错液体
24. 铁矿脉：`OreBlock` + 替换 `Planets.serpulo.generator` 子类撒矿（原版矿石清单是局部变量）
23. 存档持久化要自己重写 `version()/write/read`，`config()` 只管蓝图不参与存档（0.23.0）
22. 多配方机器要限制 `acceptLiquid` + `liquidOutputDirections`，否则相邻机器互相倒灌卡线

  用法 `git diff` / `git checkout -- <file>` 回滚；基线提交 `baseline v0.53.0`
- 分工：本地模型写机械型代码（测试、样板、脚本、文案），主模型负责架构、跨文件重构、验收
