# 铁流工业 版本变更记录（全量）

> 汇总自 `NOTES.md`（开发日志）、`docs/DESIGN.md`（设计文档）与 git 提交历史。
> **版本号规则（0.65.0.0 起）**：`a.b.c.d`，四段**按语义**递增，没有进制/满位规则。
> - `a` 大时代 / 架构级：架构重构、剧情线完结、新星球 → `a+1`，`b/c/d` 归零
> - `b` 机制 / 内容级：上新体系（算力集群、MCT 传送节点、RBMK 这类）→ `b+1`，`c/d` 归零
> - `c` 小调整 / 平衡：改炮塔伤害、改配方、调 UI 颜色 → `c+1`，`d` 归零
> - `d` 纯修 Bug：NPE 闪退、物理覆盖错位 → `d+1`
>
> 例（假设当前 `0.64.0.8`）：修 NPE → `0.64.0.9`；改天罚耗电 → `0.64.1.0`；
> 实装 RBMK → `0.65.0.0`；塞普罗剧情完结 → `1.0.0.0`。
> 用 `bash tools/bump-version.sh hotfix|patch|minor|major` 递增（加 `--next` 只试算）。
> 更早的条目用的是旧三段号，保留原样不再改写。
> 早期版本（0.0.x–0.15.x）开发日志没有逐条记录，只保留主题与关键修复。

## 1.7.x

### 1.7.0.1 — 雷达链接跨换队 + 索敌计时器

- **问题 1（主因）**：雷达把炮塔的索敌计时器设成**未来时间**。Arc 的 `Interval.check` 有“时钟回拨”保护：`Time.time < times[id]` 时直接返回 true → 炮塔自己的 `findTarget` **每 tick 都触发**，把雷达的 max-HP 目标抢成它自己的“最近敌人”（换队后就是你）。之前 T152 只检查了计时器数值，没跑实时，所以没抓到。
- **修复 1**：每 tick 把计时器按到**当前时间**（elapsed=0 < targetInterval），炮塔就不会自己找目标；解除链接时设成 `Time.time - 1000`，让它恢复。
- **问题 2**：`updateLinks` 在炮塔换队时直接删链接。链接一断，炮塔彻底回到自己的 AI。
- **修复 2**：已建立的链接**不再因换队自动断开**；只有新链接要求友军。
- 目标变成炮塔友军时，炮塔自身不会开火（除非友伤），也不会转去打玩家；连锁/溅射炮塔（如天罚）仍可能溅到目标附近的敌人，那是炮塔的连锁，不是雷达换目标。
- 全量日志器新增 `[RADAR]`（mode/links/target=type/team/hp）和炮塔 `ttgt=type/team/hp`，下次可直接对比雷达目标与炮塔目标。
- 测试：T152（换队保持 teamKeep=true）+ **T153 实时 3 秒**（雷达 max-HP 目标不能被炮塔的“最近”抢走：before=mace after=mace same=true）。

### 1.7.0.0 — 自动雷达

- **新方块**：自动雷达（3×3，效果分类），以自身为中心 **103×103 格正方形**索敌，四种模式：**血量上限最高 / 距离最近 / 最密集 / 当前血量最低**。
- **炮塔接管**：面板里点击炮塔即可链接/取消（最多 **10 个**，30 格内）；雷达每 12 tick 重选目标，把目标写进炮塔的 `target`，并把炮塔自己的索敌计时器推到很远的未来——雷达接管期间炮塔不会再自己挑目标。炮塔开火仍有原版 `within(target, range())` 判定，**不会超射程**。
- **目标标记**：目标点四枚指向中心的实心亮红色等腰三角形（四腰边互不接触）；每 **300 tick** 绕目标中心转一圈，并做约 0.7 秒一次的“心跳”缩放。标记画在所有单位之上。
- **性能**：12 tick 一次扫描 + 按 `pos()` 错开不同雷达的扫描帧；最密集模式用 8×8 格计数网格（复用 `int[1024]`，O(n)，不是 O(n²)）；每帧只画 4 个三角形；射程框和链接线只在面板打开时绘制。
- **UI**：2×2 模式按钮、链接计数、操作提示、清空链接；打开面板时画 103×103 虚线框和到炮塔的连线；关闭面板后标记仍持续追踪。
- **科技/造价**：挂在弹药组装机节点下；量子核心 2 + 碳化硅 30 + 硅 200 + 玻璃 120。
- 测试：T152（四种索敌模式 + 炮塔接管 + 计时器接管 + 10 链接上限）通过。

## 1.6.x
### 1.6.3.0 — 堆芯熔融物免疫爆炸伤害

- **问题**：反应堆爆炸的 `Damage.damage` 会把已经存在的 corium 一起打掉（沙盒 900 血直接清空；多堆连环爆时更明显，看起来像“爆炸把熔毁物也炸没了”）。
- **修复**：`CoriumBuild.damage()` 直接返回——corium **免疫一切伤害**（反应堆爆炸 / 炮火 / 核弹 / 单位），血量不再下降。
- **沙盒清理**：仍然可以**拆除**（`canBreak` 只在沙盒为 true），但不能再靠打掉；180 秒自凝固也只在沙盒发生，生存模式永久残留。
- 测试：T148 增加沙盒伤害免疫断言；新增 T151（反应堆爆炸后原地 corium 仍存活、新 corium 也生成）；RBMK 段 **37/37**。

### 1.6.2.0 — 全自动保护：按蒸汽/水位/温度快速降功率，不再“自动模式看着它炸”

- **全自动算法重写**：有效目标功率 = 滑条目标 × min(蒸汽因子, 给水因子, 温度因子)。
  - 汽包 50%→90%：功率线性降到 0；给水 30%→10%：降到 0；堆温 95%→115%：降到 0。
  - 失冷时空泡正反应性会把通量顶高，反算棒位时把 `voidFactor` 也算进去，降功率不会“降了个寂寞”。
- **保护性插棒速度 1.5 秒走完全程**（`rodSpeedAuto = 1/90`），比手动 SCRAM 的 3 秒更快，蒸汽一憋就能压下来。
- **AZ-5 保护**：水罐 >95% 且汽包满时，自动棒位最多 98%，绝不插到底；自动水位最高 90%，正常自动模式不会把水灌到 9800 L。
- **AZ-5 判定改用实际水罐 98%（9800 L）**，不再按滑条上限：手动把水位上限拉到 100% 才可能炸，调低上限就是安全操作。
- 新增状态「自动降功率：蒸汽憋压 / 给水不足」。
- 测试：新增 T149（蒸汽堵死 → 自动插棒到 100%、water 9000、不炸）、T150（给水 1000 → 自动停机）；T135c/T141/T142 复跑通过，RBMK 段 **37/37**。

### 1.6.1.0 — 汽轮机 122.5 L/s / 24000 电、温水满停机；熔融物生存模式不可摧毁

- **汽轮机**：耗汽 980 → **122.5 L/s**，冷凝水 1:1 **122.5 L/s**，发电 45000 → **24000 电/s**；一台满功率反应堆（980 L/s 蒸汽）现在配 **8 台**汽轮机。
- **温水满停机**：温水箱满了汽轮机自动停机——不再吃蒸汽、不发电、也不接受蒸汽；把温水排进冷却塔后自动恢复，避免温水被静默吞掉、蒸汽白烧。
- **堆芯熔融物**：生存模式**不可拆除**（`canBreak=false`）、**免疫伤害**、**180 秒后不再自消失**（永久残留）；沙盒模式保持原样：可拆、可打、180 秒凝固消失。
- 测试：T119/T143 数值更新；新增 T147（温水满停机/排掉恢复）、T148（corium 生存/沙盒行为）。


### 1.6.0.0 — RBMK 水/汽闭环：980 L/s、10000 L 水罐、AZ-5 憋压引爆

- **水→汽 1:1**：100% 通量 = **980 L/s 给水、980 L/s 蒸汽**（旧版按通量 × 40，满功率才 40 L/s，蒸汽少得可怜）。
- **水罐 10000 L + 汽包 2000 L**：水罐 ≈10 秒额定给水，汽包 ≈2 秒额定产汽；水/汽共用 12000 L 总容量。
- **反应堆自带给水泵**：从相邻管道/水罐主动抽水（1400 L/s），不再靠导管慢慢渗；`acceptLiquid` 只接到当前水位上限。
- **强制手动水位滑条**：手动模式面板新增「水位上限 0–100%」，超过就不再收水；半自动/全自动不接这条，后台按通量自动调（55%–90%）。
- **全自动**：滑条仍是「目标功率」，后台反算棒位（修正了旧公式少除 `fluxMax` 的偏差），并按功率自动调水位。
- **堆芯温度**：改成真实量纲的微分方程 `dT/dt = 0.14·flux − flow·(0.06 + 0.09·T) − 0.01`；满功率满给水稳定在 ~79%，断水约 9 秒到 125% 再 1 秒熔毁。
- **AZ-5 憋压引爆**：汽路堵死（汽包满）+ 水罐到当前上限 + 控制棒插到底 → 2 秒倒计时后炸堆；新增红色「憋压」状态与进度条。
- **汽轮机**：980 L/s 蒸汽 → 45000 电/s + 980 L/s 温水（1:1）；进汽侧不再倒灌温水（1.6.1.0 已调整为 122.5 L/s → 24000 电/s，见上）。
- **蒸汽只从非进水侧排出**：反应堆记录给水从哪一面进来，排汽时跳过那一面——给水泵会把进水导管抽空，空导管会接受任何液体，蒸汽灌进去就会把水管变成汽管、反应堆立刻断水（新增 T146 回归）。

### 1.2.0.0 — 核岛大修：进水修复 / 棒位上限 / 爆炸规则 / 花钱注硼 / 冷却塔 / 堆芯熔融物

- **修复（送不进液体）**：`Building.acceptLiquid()` 的实现是 `block.hasLiquids && block.consumesLiquid(liquid)`，`consumesLiquid` 查的是 **ConsumeLiquid 消费者生成的过滤器**。反应堆和汽轮机都是「手动消费液体」，没有注册消费者 → 过滤器全 false → 导管永远推不进来（冷机也不行）。现已改成显式白名单 + 容量判定，**不再调用 super**。T133a/T133b 用真实「液体源 + 导管」复现并验证。

### 0.64.8 — 算力模块占地锁死 2×3（真凶：同组方块可「合法替换」）

- **根因**：链接块当初设了 `group = BlockGroup.walls`，而引擎的 `validPlace` 允许「同组方块互相替换」（`Block.canReplace`：`group != none && other.group == 同组`，且新方块包围盒要**包含**旧方块）。于是 1×1 的墙、甚至另一台 2×2 算力模块，都能把预览压在链接块上显示可建，一点击就把链接块清掉 —— 模块随即缩回 2×2（贴图和碰撞箱一起缩）。这才是"修了半天修不好"的真正原因。
- **修复**：链接块改成 `group = BlockGroup.none` + `replaceable = false`；算力模块也把继承自 `Wall` 的 `group = walls` 改回 `none`。现在墙不能压在链接块上、模块也不能压在墙上（放置预览直接红色不可建）。
- **修复**：`ensureLinks` 改为**每 tick** 校验（日志仍按 10 tick 节流），链接块被任何手段清掉（沙盒调色板、蓝图粘贴、拆除工具）都会立刻补回，模块不会停在 2×2；补回时也允许覆盖 `alwaysReplace` 方块（与放置校验 `fitsExtra` 一致）。
- **测试**：T115a（墙/模块/集群三个方向的 `canReplace` 全 false）、T115b（强删两个链接块后自动补回，仍是 6 格 2×3 且 solid）。

### 0.64.7 — 统一集群/模块的渲染路径 + 删除白色外框

## 附：验证与部署约定

- 每个版本必须通过 `bash tools/chain-test.sh`（当前 T1–T93）再部署。
- 构建：`bash build.sh` → `out/ironworks.jar`（Android 需要 `.class` + `classes.dex`）。
- 部署：Shizuku `phone_sh` 复制到两个客户端；**必须完全重启游戏**才加载新 jar。
- 回归一次只能开一个实例；改动测试脚本时不要同时跑回归（bash 增量读取会读坏）。
