# 铁流工业 版本变更记录（全量）

> 汇总自 `NOTES.md`（开发日志）、`docs/DESIGN.md`（设计文档）与 git 提交历史。
> **版本号规则（0.65.0.0 起）**：`a.b.c.d`，四段**按语义**递增，没有进制/满位规则。
> - `a` 大时代 / 架构级：架构重构、剧情线完结、新星球 → `a+1`，`b/c/d` 归零
> - `b` 机制 / 内容级：上新体系（算力集群、MCT 传送节点、RBMK 这类）→ `b+1`，`c/d` 归零
> - `c` 小调整 / 平衡：改炮塔伤害、改配方、调 UI 颜色 → `c+1`，`d` 归零
> - `d` 纯修 Bug：NPE 闪退、物理覆盖错位 → `d+1`
>
> 例（假设当前 `0.64.0.8`）：修 NPE → `0.64.0.9`；改天罚耗电 → `0.64.1.0`；
> 实装 RBMK → `0.65.0.0`；塞普罗剧情完结 → `1.0.0.0`。
> 用 `bash tools/bump-version.sh hotfix|patch|minor|major` 递增（加 `--next` 只试算）。
> 更早的条目用的是旧三段号，保留原样不再改写。
> 早期版本（0.0.x–0.15.x）开发日志没有逐条记录，只保留主题与关键修复。

## 0.64.x

### 1.1.0.0 — 核工业全套 + RBMK 拟真化（燃料棒 / 燃耗 / 乏燃料 / 硼注入）

**核工业链**（复用 MultiCrafter，只写配方不写逻辑；加工全部沿用现有「酸」液体，不新增液体）：

```
铀矿脉 →(酸浸) 黄饼 →(离心浓缩) 浓缩铀 →(压制) 燃料棒
                                            ↓ RBMK 烧 900 秒
                                       乏燃料棒 →(水池冷却) 冷却乏燃料棒
                                            ↓ 后处理 + 酸
                                    钚 + 高放废料 →(玻璃固化) 固化废物体 →(干式储存)
```

- **新增物品 9 个**：铀矿石、黄饼、浓缩铀、燃料棒、乏燃料棒、冷却乏燃料棒、钚、高放废料、固化废物体。
- **新增方块 8 个**：铀浸出槽（3×3）、气体离心浓缩厂（3×3）、燃料元件厂（3×3）、乏燃料冷却池（3×3）、后处理厂（4×4）、固化车间（3×3）、干式储存库（3×3，只收固化废物体）、铀矿脉（塞普罗新矿石，稀疏噪声生成）。
- **RBMK 拟真化**：
  - 燃料从「直接烧钍」升级为**燃料棒**：一根满功率烧 900 秒（钍是应急替代，200 秒/根），烧完原地产出**乏燃料棒**；乏燃料排不出去就不换料（真实换料节流）。
  - 新增**燃耗**读数（当前这根烧到百分之几）、面板加「燃耗 / 硼酸浓度」两行。
  - 新增**硼酸注入**（面板第二个红/蓝按钮）：强负反应性、45 秒自然衰减，比 SCRAM 更狠，防止「插棒还能起反应」。
  - 燃料仓容量 40，且给乏燃料预留 8 格，避免烧完把自己憋死。
- **测试**：新增 T124–T132（浸出/浓缩/制棒/烧棒出乏燃料/硼注入/池冷却/后处理/固化/干储只收固化体），核工业链 10 条断言全绿。

### 1.0.2.0 — 冷却液命名与档位修正（不再和原版「冷冻液」重名）

- **来龙去脉**：0.56.0 做天罚时，为了做「无冷却 → 冷冻液 → 石墨烯冷却液」三档，加了一个模组自制冷却液（水 + 塑料 → 防冻液），本意是让石化线的塑料有用途、不依赖原版冷冻液的钛链条。**但显示名直接叫了「冷冻液」**——和原版 `Liquids.cryofluid` 完全撞名，而且天罚只认自制版、不认原版，玩家拿原版冷冻液去喂会被拒，这是设计失误。
- **修复 1（命名）**：模组液体改名为「防冻冷却液 / Antifreeze」，配方改「配制防冻冷却液」，天罚/传送带的详情文案同步说明两者同档。
- **修复 2（功能）**：天罚的冷却液档位表新增**原版冷冻液**，与防冻冷却液**同数值**（1.25× 射速 / 9%/发 / 上限 135% / 过热×0.5）；石墨烯冷却液仍是唯一会转热液的档（下标 1 不变，不影响已有存档语义）。
- **未改动**：防冻液的配方、费率、天罚的所有冷却数值一个没动；只是「多认出一种同类冷却液」+ 改名。
- **测试**：新增 T123（档位数=3、含原版冷冻液、`acceptLiquid` 返回 true）；天罚相关 85/90/91/93 全部复跑通过。

### 0.66.0.0 — RBMK 核电站（反应堆 + 汽轮机）

新增两座 5×5 / 3×3 发电建筑，**纯 2D 像素图**（没有任何 3D 体素），机制完整可玩：

- **RBMK 反应堆**（5×5）：烧钍 + 水 → 发电（满通量 45000/秒）+ 吐热冷却液（34/秒）。控制棒 0–100% 可调（面板滑条），插得越深通量越低。
  - **空泡正反应性**：冷却水不足时通量不降反升（RBMK 的经典缺陷），失冷后堆温一路爬到熔毁；
  - **氙毒（碘坑）**：功率掉下来后碘衰变成氙，短时间内压着反应性——插棒容易、拔棒难；
  - **熔毁**：堆温 ≥125% 持续 1 秒 → `Fx.reactorExplosion` + 半径 26 格 12000 伤害 + 落尘区（半径 42 格）给单位挂**辐射**状态，反应堆自身销毁；
  - 热液排不出去会**背压升温**（罐满 = 冷却失效），逼玩家把管路接好。
- **汽轮发电机**（3×3）：吃热冷却液 → 18000/秒 + 回收 90% 冷凝水，和反应堆组成闭环。
- **复用清单**（这次特意没另起炉灶）：热冷却液 / 石墨烯冷却液液体、老「冷却工厂」的热液回收配方、原版钍当燃料、现有材料（碳化硅 / 钢板 / 量子核心 / 航空铝）当造价、`IronworksStatus` 状态框架加一条 `radiation`、MCT 节点的 `config` + `buildConfiguration` UI 模式、`Gen.java` 像素画生成器。
- **UI**：方块的配置面板里有控制棒滑条、通量 / 堆温(K) / 氙毒 / 冷却读数、状态提示（稳定 / 缺水 / 过热 / 熔毁）、SCRAM 按钮；方块身上挂 5 条状态条（功率 / 堆温 / 氙毒 / 冷却 / 燃料）。
- **测试**：T116 发电 + 热液、T117 插棒降功率、T118 失冷升温、T119 汽轮机发电 + 回水、T120 熔毁（爆炸伤害 + 辐射）。测试用 `build.updateTile()` 手动步进，不阻塞服务器线程。

- **新增：设置分类「铁流工业」**（`IronworksSettings`）——方块搜索的两项开关 + 暂停模式/请求开关/白名单管理按钮；分隔线用 `Setting` 子类注册，切分类/恢复默认不会被删。

### 0.64.8 — 算力模块占地锁死 2×3（真凶：同组方块可「合法替换」）

- **根因**：链接块当初设了 `group = BlockGroup.walls`，而引擎的 `validPlace` 允许「同组方块互相替换」（`Block.canReplace`：`group != none && other.group == 同组`，且新方块包围盒要**包含**旧方块）。于是 1×1 的墙、甚至另一台 2×2 算力模块，都能把预览压在链接块上显示可建，一点击就把链接块清掉 —— 模块随即缩回 2×2（贴图和碰撞箱一起缩）。这才是"修了半天修不好"的真正原因。
- **修复**：链接块改成 `group = BlockGroup.none` + `replaceable = false`；算力模块也把继承自 `Wall` 的 `group = walls` 改回 `none`。现在墙不能压在链接块上、模块也不能压在墙上（放置预览直接红色不可建）。
- **修复**：`ensureLinks` 改为**每 tick** 校验（日志仍按 10 tick 节流），链接块被任何手段清掉（沙盒调色板、蓝图粘贴、拆除工具）都会立刻补回，模块不会停在 2×2；补回时也允许覆盖 `alwaysReplace` 方块（与放置校验 `fitsExtra` 一致）。
- **测试**：T115a（墙/模块/集群三个方向的 `canReplace` 全 false）、T115b（强删两个链接块后自动补回，仍是 6 格 2×3 且 solid）。

### 0.64.7 — 统一集群/模块的渲染路径 + 删除白色外框

- **修复（实现不一致）**：高级算力模块 `extends Wall`，而 `Wall.init()` 会**强制** `drawCached = true`、`drawDynamic = false`，于是它的贴图走 30×30 区块的 `SpriteCache`（只在换块事件时重建、超出区块边界会被裁），`canOverdrive` 也被设成 false；而全域算力集群是普通 `Block`，逐帧绘制。两者因此不是"只差尺寸"。现在在 `ComputeModule.init()` 里把 `drawCached/drawDynamic` 改回逐帧绘制，`canOverdrive` 与集群统一为 true。
- **修改（UI）**：删除放置预览与选中时的**白色 2px 外框**（集群与模块都删），真实占地只保留链接块那一圈淡紫色格子提示；选中框两个方块统一走 `drawFootprint()`（Pal.accent / 1.5px）。
- **测试**：新增 T114a/b/c —— 逐项比对模块与集群的 `drawCached/drawDynamic/canOverdrive/solid`，并实测占地（模块 6 格 2×3、集群 24 格 4×6）与贴图相对引擎中心的下移量（-4 / -8）。

### 0.64.6 — 修复 2×2 链接块吞建筑 + 箭头速度按 tick 计算

- **修复**：主集群的链接块是 2×2，但之前只检查了锚点那一格是否为空；当 2×2 的另一格有建筑时，`setBlock` 会把整个 2×2 清掉，把那一格的建筑吞掉。现在会检查链接块的**完整占地**，任何一格被占就跳过不生成。
- **修改**：跃迁节点的方向箭头改为按 tick 累计进度（16 单位/秒 = 2 格/秒），不再依赖 `Time.time` 的单位，速度精确且不会因游戏运行时间长而抖动。
- **测试**：新增 T112（链接块另一格有钍墙时不生成链接、墙保留）；节点/集群子集 6 条断言全绿。


### 0.64.5 — 真实占地框更醒目

- **修改**：放置 4×6 / 2×3 机器时，用**白色粗线**画出真实包围盒，并给链接块格子加淡色填充；引擎自带的黄色框只覆盖 2×2 核心，两者区分开后不会再误以为“贴图偏移”。
- **说明**：机器的真实占地 = 核心 2×2 + 下方 1 行（或 4×4 核心 + 下方 2 行）链接块；引擎的放置框只按 `size` 画核心，这是原版限制。
